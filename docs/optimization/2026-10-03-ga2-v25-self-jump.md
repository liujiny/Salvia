# GA2: batch V25 protection CPU self-jumps

Baseline: `65bfe3403ce45a94812e25aa048eb521e1454008`.

## Reason and scope

In the local 3,000-frame GA2 replay, the V25 executed approximately 41.7
million short jumps back to itself at PC `0x422`. A separate stage profile
spent about 0.21 ms per host frame on this CPU. These are host observations,
not Xbox timings.

GA2 now explicitly opts its directly mapped protection ROM into self-jump
batching on Xbox. The core recognizes a normally executed `EB FE` by its
decoded opcode, unchanged PC and actual 12-cycle cost. It does not hard-code
the observed PC, skip protection initialization or remove the V25.

Only complete subsequent jumps are charged. The prefetch queue must already
be full and able to refill both instruction bytes in 12 cycles. Batching
stops strictly before the earliest enabled timer expires; the original
instruction loop handles expiry, periodic reload and interrupts. Pending
unmasked interrupts, trap/prefix state and stop requests disable batching.
Other drivers do not opt in. Configuration remains outside serialized state.

- `python3 libretro/FBNeo/tests/v25_wait_loop/test.py`: PASS, ASan/UBSan;
  20,000 randomized prefetch/timer cases, one-shot/periodic/simultaneous timers,
  interrupt boundaries, cycle remainders and opt-in guards.

- Headless replay from reset, 4,000 frames: all per-frame video/audio hashes
  and final serialized state match the baseline.
- Loaded-state replay, 6,000 frames, two rendering workers: video/audio hashes
  and state match the prior checkpoint. SHA256 of `hashes.txt`:
  `34b42788d71703bc17d9b3b8946f0d87263e5eb7dd33d964790fc202d52fa5c6`;
  state: `f956cf6a2b5af163e3d9893c0b54db1e0c3330e99cd9e3e1f4f2fb2e7eb67ca3`.
- `python3 /home/humor/salvia-tests/ga2/v25-idle/ppc-test.py`:
  actual big-endian PowerPC execution under QEMU, 1,200 frames from reset;
  per-frame video/audio, final state and raw frame match. State SHA256:
  `5c33ee1179595aa6bd87720e46d7e855343638328e593028fe5929aa639790e7`.
- Sequential host A/B/B/A timing, 3,000 frames each, two rendering workers:
  baseline **1.8550 / 1.8565 ms/frame**;
  candidate **1.6952 / 1.7109 ms/frame** (about 8.2% lower average time).

The replay covers its scripted input sequence, not every game scene. QEMU
checks endian/cycle/state behavior; it does not measure Xenon performance.
There are no production profiling counters or new runtime logs.
